# 生成结果诊断：`�` 乱码与语料质量

针对这条命令的输出做的分析：

```bash
python sample.py --device cuda:1 --prompt "今天去哪里玩" --max-new-tokens 32
```

```
今天去哪里玩��了�你的事情
<|用户|>好的，谢�
```

**结论：这里有两件独立的事，必须分开看。**

1. 输出里的 `�` 乱码 —— 是**采样脚本的 bug**，与数据集无关。
2. 「训练数据集合的质量好像一般」—— **这个判断是对的**，我最初低估了。

---

## 一、`�` 乱码：不是数据集的问题

### 现象还原

你的 checkpoint 其实是**健康的**。同一份权重，换成带角色标记的 prompt 立刻正常：

| prompt | 输出 |
|---|---|
| `今天去哪里玩`（裸） | `今天去哪里玩��了�你的事情` ❌ |
| `<\|用户\|>今天去哪里玩\n<\|助手\|>` | `其实社交聚会因人而异，这个方法效果很好` ✅ |

模型没坏，坏的是「怎么问」和「怎么解码」。

### 根因：tiktoken 把中文拆成「半个字」

gpt2 词表以英文为主，对中文是**逐字节**切分的。实测「玩」这个字：

```
'玩' = UTF-8 字节 E7 8E A9
      ↓ tiktoken 切成 3 个 token
      id=163  ->  b'\xe7'   (第 1 个字节)
      id=236  ->  b'\x8e'   (第 2 个字节)
      id=102  ->  b'\xa9'   (第 3 个字节)
```

单独 decode 任何一个，都得不到合法 UTF-8，于是吐出 `U+FFFD`（就是 `�`）。

实测「今天去哪里玩」= **13 个 token**，其中 12 个单独解码都含 `�`：

```
len= 1  decode='�'        <<< 
len= 4  decode='今天�'     <<<
len= 6  decode='今天去�'   <<<
...
len=12  decode='今天去哪里�'  <<< 最后一个 token 只是残缺字节
len=13  decode='今天去哪里玩'   ← 完整才无损
```

**所以 `�` 出现在 prompt 与生成内容的交界处**：prompt 最后一个 token 是残缺字节，
而模型生成的第一个 token 不是它的补位字节，这个残缺字节就永远无法组成合法 UTF-8。

### 三重放大

你的命令里三个因素叠加，把问题放大了：

1. **`--prompt "今天去哪里玩"` 裸喂**。训练语料每一轮都以 `<|用户|>` / `<|助手|>` 开头
   （实测：`'<|用户|>'` = 8 tokens，`'<|助手|>'` = 8 tokens）。裸 prompt 是分布外输入。
2. **prompt 恰好在 3 个残缺字节的中间截断**（见上面 13-token 表）。
3. **原 `sample.py` 是无 top-k、无温度的纯多项式采样**，在 50,257 词表上极易抽到
   生僻 token 和乱码组合。而且它解码**整个序列**（prompt + 生成），把 prompt 末端的
   残缺字节也纳入了。

### 修法

新脚本 `generate.py` 四件事一起做：

1. **只解码新生成的 token**（`idx[0, n_prompt:]`），prompt 末端的残缺字节根本不进解码范围；
2. **`safe_decode()`**：按 token 取字节流后用 `errors="ignore"` 宽松解码，从源头不产生 `�`；
3. **默认用 `--chat` 包成 `<|用户|>…\n<|助手|>`**，进到训练时见过的分布；
4. **默认 top-k=40 + temp=0.8**，并提供 `--greedy` 确定性解码。

实测（你的原 prompt，同一个 `model_epoch_4.pt`）：

```bash
python generate.py --device cuda:1 --prompt "今天去哪里玩" --max-new-tokens 32
#  Generated: 求助！急！在线等！

python generate.py --device cuda:1 --prompt "今天去哪里玩" --max-new-tokens 40 --greedy
#  Generated: 其实社交聚会因人而异，这个方法效果很好
```

`�` 完全消失。

### 一个容易踩的细节：`--terminate`

包 prompt 时有个坑。训练语料里：

```
<|用户|>A\n<|助手|>B\n<|用户|>C\n<|助手|>D\n\n
                ↑ <|助手|> 后面直接跟内容，不换行；而 <|用户|> 后面永远有换行
```

如果在 `<|助手|>` 后再补一个 `\n`，就造出「`<|助手|>` 紧接空行」这种语料里不存在的状态，
模型会认为「本轮说完了」，立刻输出 `<|用户|>` 开启下一轮，回复内容反而没了：

```
# 补了 \n（错）
Generated (32 tokens) = 其实社交聚会因人而异，这个方法效果很好，你可\n<|用户|

# 停在 <|助手|>（对，默认行为）
Generated (48 tokens) = 其实社交聚会因人而异，这个方法效果很好，你可
```

所以默认 `--terminate` 让 prompt 恰好停在 `<|助手|>`。

## 二、语料质量：你的判断是对的

我最初验收时只验证了「数据能被正确读取、格式无损」，**没有做内容质量体检**，
这是我的疏漏。补做之后，你的感受得到了数据支持。

### 实测数据

```
对话总数       95,000
发言总数      427,628
唯一发言       61,705
重复率         85.6%     ← 
```

出现最多的单条发言：

| 次数 | 发言 |
|---|---|
| 9,098 | `<\|用户\|>哇塞，真的吗？` |
| 9,051 | `<\|用户\|>有点道理` |
| 9,047 | `<\|用户\|>好有道理的样子` |
| 9,012 | `<\|用户\|>好的好的，我明白了` |
| 8,986 | `<\|用户\|>感觉很有帮助！` |

**根源**：HANA 是从一个**固定回复池**里组合生成的。生成器把池子里的句子随机排列，
所以「整条对话」几乎不重复（95,000 条里只重复 24 条 = 0.0%），
但**组成它的句子**大量复用。这解释了为什么：

- `train_loss` 能降到很低、`val_loss` 只有 **0.16** —— 模型把模板背下来了；
- 生成内容高度雷同 —— 因为语料本身就只有那几百个句式。

> ⚠️ **注意：`val_loss = 0.16` 是个陷阱。** 它看起来非常漂亮，但那是因为
> 训练集和验证集共享同一个回复池，模型学到的是「模板」，不是「语言」。

### 更精确的定位

```
出现 >200 次的高频发言种类: 79  （仅占唯一发言的 0.1%）
这 79 句贡献的发言量占比:      53.5%      ← 0.1% 的句子撑起了一半的语料
```

### 处理：降采样，不删数据

`dedup_data.py` 对**含高频发言的对话**做降采样（而不是删掉高频句，那会毁掉组合多样性）：

```bash
python dedup_data.py --report                      # 只体检
python dedup_data.py --max-utterance-freq 200 --keep-ratio 0.35   # 生成降采样版
```

实测效果：

| 指标 | 原版 | 降采样版 |
|---|---|---|
| 对话数 | 95,000 | 33,909 |
| 发言数 | 427,628 | 151,613 |
| 唯一发言 | 61,705 | 36,244 |
| **重复率** | **85.6%** | **76.1%** |
| 字符数 | 9.48M | 3.20M |

产出 `data/train.dedup.jsonl` / `data/val.dedup.jsonl`，**原文件不动**。
换用只需把 `train.py` 里的 `path` 改掉。

## 三、要「更高质量」，根本解是换语料

降采样只能把重复率从 85.6% 压到 76.1% —— 因为**模板化是数据集的固有属性**，
不是靠清洗能救的。如果目标是「让模型学会好好说中文」，建议换一个**人工撰写**的语料。

### 推荐：中文古诗/古文语料

对「小 GPT 学中文」这件事，古诗文其实比闲聊对话**更合适**：

| 维度 | HANA 闲聊 | 古诗文 |
|---|---|---|
| 句式多样性 | 低（79 句占 53%） | 高（几乎无重复） |
| 内容质量 | 机器拼接，语义常不通 | 人工创作，质量极高 |
| 长度 | 短，适合 `block_size` | 短，天然就是一段 |
| 学习信号 | 只学到「回复风格」 | 能学到真实的中文词汇/语法/韵律 |
| 过拟合后表现 | 复读模板句 | **能背出整首原文** ← L06 的过关标准 |

L06 的过关标准原文是「能生成非乱码文本（过拟合语料上应能认出原文碎片）」。
古诗文语料在这个标准上会表现得非常漂亮，而 HANA 只会输出那几句套话。

候选（ModelScope，均已确认可访问）：

| 数据集 | 大小 | 说明 |
|---|---|---|
| `modelscope_mp_827305057/Chinese_Poetry_Dataset` | — | 中国古诗词全集 |
| `nnnnnereo/gushicidata` | 0.1 MB | 古诗词数据（轻量） |
| `ovo0620/yuefushi` | 0.2 MB | 古诗文网乐府诗精选 |
| `duanyu/ai_chinese_poetry_modern_translation` | 6.7 MB | 古诗词 + 现代文翻译对照 |

### 换语料的方法

`prepare_data.py` 是为 HANA 的 `{"batch_info","dialogues"}` 结构写的。
换数据集只需改两处：

1. `DATASET_ID` 改成新数据集名；
2. `iter_dialogues()` 和 `render_dialogue()` 适配新结构。

如果需要我接一个新的中文语料（比如古诗全集，或别的），说一声即可。

## 四、当前建议

按优先级：

1. **先修采样脚本** —— 用 `generate.py` 替代 `sample.py`。这一步立刻解决 `�`，
   不涉及重新训练：
   ```bash
   python generate.py --device cuda:1 --prompt "今天去哪里玩" --greedy
   ```
2. **别被 `val_loss=0.16` 骗了** —— 用生成质量判断，不要只看 loss。
3. **想继续用 HANA** —— 试试降采样版：
   `train.py` 里改 `path="data/train.dedup.jsonl"`。
4. **想要质的提升** —— 换古诗文语料重训。这是唯一能真正摆脱模板化的路。
